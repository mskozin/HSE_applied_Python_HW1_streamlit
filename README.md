# Отчет по выполнению домашней работы: Анализ температурных данных и мониторинг текущей температуры через OpenWeatherMap API

## 1. Эксперименты с синхронными и асинхронными запросами

Проведено несколько экспериментов с запросом погоды разного количества городов.

### Результаты:

#### 🔹 Для 5 городов
- **Синхронный подход:** `2.01`, `2.02`, `1.93` секунд
- **Асинхронный подход:** `0.16`, `0.16`, `0.17` секунд
- **Средний выигрыш:** **12.6×**

#### 🔹 Для 10 городов
- **Синхронный подход:** `4.07`, `4.00` секунд
- **Асинхронный подход:** `0.19`, `0.18` секунд
- **Средний выигрыш:** **22×**

#### 🔹 Для 20 городов
- **Синхронный подход:** `7.93` секунд
- **Асинхронный подход:** `0.22` секунд
- **Средний выигрыш:** **36.9×**

### 📝 Вывод:
Запрос к удаленному серверу — это **IO-bound (Input/Output bound) задача**. Асинхронные функции позволяют значительно сократить время работы программы с задачами такого типа.

## 2. Эксперименты с параллельной обработкой датасета

### ⏱ Результаты измерений:
- **Последовательный анализ:** `0.12`, `0.11`, `0.12`, `0.13`, `0.12`, `0.11`, `0.11`, `0.11`, `0.12` секунд
- **Параллельный анализ:** `1.76`, `1.56`, `1.57`, `1.56`, `1.54`, `1.58`, `1.58`, `1.54`, `1.54` секунд

### 📝 Вывод:
Использование независимых процессов при помощи `ProcessPoolExecutor` из `concurrent.futures` оказалось слишком тяжеловесным для данной задачи. Накладные расходы на создание процессов не оправдали себя при обработке такого маленького датасета.

## 3. Структура проекта

### 📂 **Файл `app.py`**
- Основное приложение, «точка входа»

### 📂 **Файл `analysis.py`**
Содержит функции для анализа исторических данных:

#### **А) Функция `analyze_city`:**
- Рассчитывает скользящее среднее по 30 дням
- Рассчитывает стандартное отклонение по 30 дням
- Определяет аномальные значения — те, что отличаются от скользящего среднего больше чем на ±2σ
- Вычисляет среднее значение и стандартное отклонение по сезонам
- Определяет долгосрочный тренд

**Возвращает словарь**, содержащий:
- Название города
- Датасет с добавленными рассчитанными значениями
- Таблицу со статистиками по сезонам
- Коэффициент тренда

#### **Б) Функция `sequential_analysis`:**
- Берет все исторические данные
- Разбивает их по городам
- Последовательно применяет `analyze_city` к каждому городу

#### **В) Функция `parallel_analysis`:**
- Берет все исторические данные
- Разбивает их по городам
- Параллельно применяет `analyze_city` к городам

### 📂 **Файл `weather_api.py`**
Содержит класс `WeatherAPI` с двумя методами для запроса данных о погоде в OpenWeatherMap API:

#### **А) Метод `get_current_weather_sync`**
- Предназначен для запросов в синхронном режиме

#### **Б) Метод `get_current_weather_async`**
- Предназначен для запросов в асинхронном режиме

#### **Дополнительная функция:**
- `check_anomaly` — определяет, является ли текущая температура нормальной, исходя из исторических данных для текущего сезона

### 📂 **Вспомогательные файлы для экспериментов:**
- `seq_vs_par_comparison.py` — для сравнения времени работы последовательного и параллельного подходов
- `sync_vs_async_comparison.py` — для сравнения времени запросов в синхронном и асинхронном режимах
